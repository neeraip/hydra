The engines

Two engines today, a third planned

Each engine owns its data model end to end: reader, solver, and report. Correctness is defined by Hydra's own convergence criteria and physical conservation laws, with file-level compatibility with each engine's predecessor.

Available

Water distribution

EPANET data model

A Global Gradient Algorithm hydraulic solver and a Lagrangian water quality engine. Reads any EPANET 2.x .inp file; writes EPANET-compatible binary results and text reports.

Available

Urban drainage

SWMM data model

Rainfall-runoff hydrology, dynamic-wave routing, and water quality on the SWMM data model: infiltration, LID controls, snowmelt, groundwater, pollutant transport.

Planned

Open channel

HEC-RAS data model

The next engine on the roadmap. Its place in the toolchain is reserved; it is not yet implemented.

One toolchain

The same engines on every surface

Desktop app

Import a model, edit the network on a map, run scenarios in a background queue, and explore results. Both engines are supported.

CLI

Run hydra run model.inp. The model's own sections identify the engine, and one command produces the report, the binary results, and the analytics.

Rust SDK

The engines as a library. One crate, hydra-sdk, is the public API the desktop app and CLI are themselves built on.

Browser

The real engines, compiled to WebAssembly. Drop a model on the demo. It is read, solved and reported in your tab, and never uploaded.
